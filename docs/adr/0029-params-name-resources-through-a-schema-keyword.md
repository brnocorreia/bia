# Params name Queues and Workflows through a schema keyword

Validation must check that a Queue or Workflow a Step names exists (ADR-0015), but Params are an open object (ADR-0024), so only the Action knows which param is a name. An Action marks such a param in its param schema with the annotation `"x-bia-resource": "queue"` or `"x-bia-resource": "workflow"`, on a property reached through `properties` from the schema root. JSON Schema validators ignore unknown keywords, so the mark changes nothing else, and it travels with the descriptor, so Action Servers can use it without bia knowing their Actions. Hard-coding `queue.publish` and `flow.subworkflow` in validation would have been simpler today, but would tie `bia-core` to builtin Action names and leave every other Action unchecked. Only literal names are checked, since a Template resolves at execution time, and subschemas behind `$ref`, `oneOf` or `items` are not followed. Supporting them later only adds checks.
