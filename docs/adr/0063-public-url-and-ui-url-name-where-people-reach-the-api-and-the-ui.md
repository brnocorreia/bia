# `public_url` and `ui_url` name where people reach the API and the UI, defaulting to the listening address with `localhost` for loopback

Links the server hands out (the Setup Link now; OAuth issuer and redirect URIs, the WebAuthn origin and the cookie's `Secure` flag later) must name the URL a person's browser uses, which the server cannot infer from its bind address behind a proxy, so it is configured. `public_url` (`BIA_PUBLIC_URL`) is where the API is reached and `ui_url` (`BIA_UI_URL`) where the UI is, defaulting to `public_url` because the embedded UI is served by the API (ADR-0052); a separately hosted UI sets it. Without `public_url` the default is `http://` plus the address the API actually listens on, so a `:0` bind names the real port, with a loopback or unspecified address (`127.0.0.1`, `::1`, `0.0.0.0`, `::`) written `localhost`: browsers treat `localhost` as a secure context, which passkeys need, and no one can open a link to `0.0.0.0`. Both must be absolute `http` or `https` URLs with a host and without credentials, a query or a fragment, since bia appends its own paths; a path is allowed for a UI hosted under one, and a trailing slash is ignored. An invalid value stops `bia serve` and `bia migrate` at startup with the key named, as other configuration does (ADR-0037), instead of producing broken links later.
