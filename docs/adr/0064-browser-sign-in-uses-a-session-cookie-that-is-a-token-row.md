# Browser sign-in uses a Session cookie that is a Token row, with an Origin check for CSRF, credentialed CORS for the UI's origin only, and an in-memory throttle

This supersedes ADR-0050 and the Scope-from-the-Token mechanism of ADR-0053, and lets the UI hold a credential no script can read. ADR-0050 rejected a cookie because the UI had no backend to set one; the UI is now served by `bia-server` (ADR-0052), and a separately hosted UI must be same-site with the API. `POST /v1/session` takes `{password}` and sets `bia_session`: a Token value (ADR-0043's format and hash) stored as a row with `origin = session` and the `admin` Scope, kept in a new `tokens.origin` column (`session`, `oauth`, `manual`; existing rows become `manual`). The cookie is `HttpOnly` and `SameSite=Lax`, `Secure` when `public_url` is HTTPS, has no `Domain`, and carries `Path=/` (a default path would hide it from `/mcp` and `/hooks`) and a `Max-Age` of the 90-day ceiling, so it survives a closed browser while the server decides when it ends. Only a Session expires: after 14 days unused (`last_used_at`, recorded to the minute, else `created_at`) or 90 days after creation, judged against the injected `Clock` when the Token is looked up, so nothing sweeps rows and a test moves the Clock. `DELETE /v1/session` revokes the caller's Session and clears the cookie, and `POST /v1/setup` starts a Session instead of returning an interim Token. The `Admin`, `Agent` and `Webhook` extractors accept the bearer header or the cookie, the header winning; a cookie must hold a `session` Token, and `/mcp` accepts only the header, since its tools forward the header and a cookie there would invite cross-site calls. Against CSRF, a request authenticated by the cookie with an unsafe method (anything but GET, HEAD, OPTIONS, TRACE) must carry an `Origin` equal to the origin of `public_url` or `ui_url`, else 403 `origin_mismatch`; a bearer request needs none, since a page cannot set that header without CORS. We chose this over a CSRF token because the UI is a static bundle with no page to embed one in, and `SameSite=Lax` alone does not protect same-site siblings. CORS answers any origin of `cors_origins` as before, and also `ui_url`'s origin, and sends `Access-Control-Allow-Credentials` to `ui_url`'s origin only, so `*` and the listed origins stay credential-less. Failed sign-ins are throttled in memory per User and peer address: from the sixth consecutive failure an attempt waits 1 s, doubling to a minute, before it is checked, and an attempt counts as failed until it succeeds, so parallel guesses wait like sequential ones; a success clears the count, and nothing locks. The wait goes through an injectable `Wait`, so tests record it instead of sleeping. Behind a proxy the peer address is the proxy's and forwarded headers are not trusted, which makes the throttle per User; each API process counts on its own. `POST /v1/user/password` takes `{current, new}`, counts a wrong `current` towards the same throttle, and revokes every other Session in the same transaction, leaving OAuth Grants and manual Tokens alone. A wrong password answers 401 `invalid_credentials`, so the UI signs out only on the codes `missing_token` and `invalid_token`, not on any 401. The UI keeps nothing in storage: it asks `GET /v1/tokens/me` on load and after sign-in, and a 401 right after a successful sign-in means the cookie was dropped, so it explains the same-site rule.
