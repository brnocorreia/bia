# API routes live under /v1, every error has one body with a stable code, and API tests run an in-process server per test

Every later endpoint and every MCP tool name inherits the conventions the first endpoints set, so they are fixed here. Resource routes live under `/v1` (`/v1/schema`, then `/v1/workflows/...`), with plural lowercase nouns, path segments for ids, `POST .../<verb>` for operations that are not reads or writes of a resource (e.g. `.../publish`), and snake_case JSON fields; a breaking change ships as `/v2` next to `/v1`, while adding routes, fields and error codes is not breaking. Probes and documents a caller needs before knowing the version, `/health`, `/ready` and `/openapi.json`, live at the root, as do `/mcp` and `/hooks/{workflow_id}/{trigger_id}` (ADR-0015). Each handler's function name is its OpenAPI `operationId` and the name of the MCP tool that mirrors it (`get_schema`), so the two surfaces cannot drift in naming. Every non-2xx response, unknown routes and methods and rejected bodies included, is `{ "code", "message", "diagnostics"? }`: the HTTP status gives the class, and `code` is a snake_case phrase naming the problem, following ADR-0028 for the same reasons, from the `bia_server::ErrorCode` enum, which may grow but whose codes are renamed or removed only with an ADR; `diagnostics` carries every Diagnostic, warnings included, whenever a Definition caused the error, so `bia-client`, the UI and agents read validation results the same way from any endpoint. `message` never carries internal error text, which is logged instead. The OpenAPI document is generated with `utoipa` from the handlers, served at `/openapi.json` and committed at `crates/bia-server/openapi.json`, which a test compares byte for byte, so API changes show up in review and the UI can generate types from the file. HTTP API tests (`crates/bia-server/tests/common`) start a server per test on a free loopback port over the database `#[sqlx::test]` creates for that test, and drive it through `bia-client`, so tests share nothing and need only `docker compose up`; starting a server costs about a millisecond, which a shared server would not save enough to justify shared state between tests.
