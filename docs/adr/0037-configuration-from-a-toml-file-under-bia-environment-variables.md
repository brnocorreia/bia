# Configuration comes from a TOML file under `BIA_*` environment variables

`bia serve` and `bia migrate` read their configuration once at startup, and the names become a contract with every deployment, so they are fixed here. Values come, lowest precedence first, from built-in defaults, an optional TOML file named by `--config` or `BIA_CONFIG`, `DATABASE_URL`, and `BIA_*` variables, so a container can override any file setting without rewriting it and `DATABASE_URL` works as it does for `sqlx` and most hosting platforms. TOML is used because the file is flat, hand-edited settings, which YAML's indentation and implicit typing serve worse; Definitions stay JSON or YAML. A file key `section.name` is the variable `BIA_SECTION_NAME` (`worker.poll_interval` is `BIA_WORKER_POLL_INTERVAL`), and a top-level key `name` is `BIA_NAME`, which keeps names already promised by earlier ADRs (`BIA_MASTER_KEY`, `BIA_RUN_RETENTION_DAYS`, `BIA_CORS_ORIGINS`) as top-level keys; a section therefore owns its prefix, and no top-level key may start with a section's name. Durations are written as in the DSL (`30s`, `5m`). Unknown keys in the file fail startup, so a typo is caught, but `BIA_*` variables that name no key are ignored, because an environment is shared with other tools and with settings later releases read. Invalid configuration fails before anything starts, naming the key and the file or variable its value came from. The keys are listed in `docs/configuration.md`.
