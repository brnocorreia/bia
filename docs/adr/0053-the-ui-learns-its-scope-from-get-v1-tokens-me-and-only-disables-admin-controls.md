# The UI learns its Scope from `GET /v1/tokens/me` and only disables admin controls

The UI must not offer publish, activate or administration to a Token that cannot use them, but the Token it holds is an opaque string and the API had no route that says what it is. We added `GET /v1/tokens/me`, open to `admin` and `agent` Tokens, which returns the caller's own `TokenInfo` (never its value); the UI reads it once per session Token and exposes it through `useCurrentToken`, `useIsAdmin`, `AdminOnly` and `RequireAdmin`. We rejected decoding the Scope from the Token (values are random, ADR-0043) and probing an admin route and reading the 403, which has side effects or noise and cannot tell "agent" from "webhook". Admin-only controls are shown disabled with an explanation instead of hidden, so an agent Token's user sees why a button is unavailable, and they stay disabled while the Scope is loading. This is only a convenience: the server enforces the Scope on every request, and a 403 that still arrives is shown as a message rather than treated as a sign-out.
