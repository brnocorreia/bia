# A Dry Run drives the interpreter's own transitions in memory, and Mocks are keyed by Step id

A Dry Run must behave like a real Run, so it reuses the interpreter instead of copying it: `Interpreter::dry_run` calls the same `start` and `step` transitions a Worker does and keeps the Checkpoint in a local `Run`, so nothing reaches Runs, Timelines or Jobs and no transaction is opened, which a rolled-back transaction could not promise for Actions that write elsewhere. Waits resolve instantly because the loop runs on a virtual Clock that jumps to the time the next Job would have been claimable (a sleep's wake-up, a retry's backoff) instead of waiting; timeouts still count real time, and Timeline entries carry the virtual times, so a `flow.sleep: 3d` entry shows a duration of three days. `POST /v1/workflows/{id}/versions/{n}/dry-run` (`dry_run_version`, a Draft or Published Version) and `POST /v1/dry-run` (`dry_run_definition`, a Definition in the body) take `{ input?, mocks? }` and answer `{ dry_run: true, status, input, timeline, diagnostics }`, where `timeline` entries are rendered by the very code that renders a real Run's (ADR-0045), and `status` is `succeeded` or `failed`. A Definition with error Diagnostics is refused with `invalid_definition`; input is checked against `input_schema` inside the Dry Run, so a mismatch is a failed Timeline like a real Run's. `mocks` maps a Step id to exactly one of `{ "output": <any JSON> }`, `{ "error": { "class": "retryable" | "fatal", "message", "details"? } }` (an error goes through the Step's retry policy like a real one), or `{ "attempts": [ {output} | {error}, ... ] }`, where the Nth Attempt gets the Nth outcome and the last repeats, which is how a Dry Run fails twice and then succeeds. Keying by Step id leaves room for loop iterations later (`iteration_path`). Without a Mock, a `pure` Action runs for real and a `side_effecting` one returns its first example's Output, or fails the Attempt with the code `no_mock` when it has none; a Mock on a `pure` Step overrides it, so a caller can force a failure. A Mock naming a missing Step, a `flow.*` Step or a Block, or not in this format, is refused with `invalid_mock` before anything runs, since it is nearly always a typo; forcing `if` and branch outcomes is not offered, as the input already steers them. Secrets are not resolved in a Dry Run: `secrets.NAME` reads a placeholder (`<secret NAME>`), so a Dry Run needs no Secret Provider and cannot reveal a value, and the Timeline shows the Template as written, as a real Run's does (BIA-26 may add an existence check that reports an unknown name as a warning, but must not make the Dry Run read values). A Dry Run is cut off with `dry_run_too_long` after 10,000 transitions, so a huge retry budget cannot hold a request.
