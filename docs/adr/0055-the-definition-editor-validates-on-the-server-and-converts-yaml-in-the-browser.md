# The Definition editor validates on the server and converts YAML in the browser

The editor needed schema-aware completion and Diagnostics, and the server accepts only JSON (docs/dsl.md). We use Monaco with `monaco-yaml` and the JSON language service for completion and hover from `GET /v1/schema`, but turn their client-side validation off: the only underlines are the server's Diagnostics from `POST /v1/validate` (debounced), mapped from JSON Pointer to a text range in the JSON or YAML source, so there is one source of truth and one wording. For completion the schema is loaded without its `required` lists, because the language service hides `oneOf` variants a half-written object fails, which would hide `cron` and `queue` Triggers until their fields exist. YAML is parsed with the `yaml` package and sent as JSON; the editor keeps no YAML source (reopening shows the stored Definition as YAML), and warns that YAML comments are lost rather than refusing them. Monaco and its workers are bundled, with no CDN, so the embedded UI's CSP needs no change (ADR-0050, ADR-0052); `monaco-editor` is pinned to 0.54 because `monaco-yaml` 5.5 imports paths that 0.57's export map dropped.
