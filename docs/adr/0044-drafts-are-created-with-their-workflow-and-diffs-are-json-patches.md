# A Workflow is created by its first Draft, Drafts are replaced in place, and Version diffs are JSON Patches

The Version routes are public API that agents and the CLI build on, so their shape is fixed here. There is no `POST /v1/workflows`: `POST /v1/workflows/{id}/versions` takes a Definition and creates the Workflow if it is new, because a Workflow with no Version is of no use and agents then need one call, not two. The body is the Definition itself, whose `id` must equal the path (`workflow_id_mismatch`), and `PUT /v1/workflows/{id}/versions/{n}` replaces a Draft keeping its number (`version_published` once Published, never reopened). Any number of Drafts may coexist, since a limit would only make agents delete work and publishing one Draft leaves the others untouched. Saving a Draft needs only a body that parses as a Definition (otherwise `invalid_definition`), so work in progress with semantic errors is kept and its Diagnostics come back in the response; publishing (`POST .../versions/{n}/publish`, `admin`) validates for the Publish target inside the transaction that freezes the Version and refuses with the Diagnostics if any is an error, and fails with `version_changed` if the Draft was replaced after it was validated. Activation and rollback are one route, `POST .../versions/{n}/activate` (`admin`), which needs a Published Version; the scheduler finds the change by comparing `active_version` with `scheduled_version` on its next tick, so activation notifies it through the database and needs no in-process channel, which works across processes (ADR-0005). Validation without saving is `POST /v1/validate` for a body and `POST .../versions/{n}/validate` for a stored Version, each with `?target=draft|publish`, and returns 200 with the Diagnostics. A diff, `GET /v1/workflows/{id}/diff?from=&to=`, is an RFC 6902 JSON Patch between the two canonical Definitions: structured, which agents can read per field and the UI can render, and it is computed on request, never stored. We rejected a textual diff, which depends on key order and formatting. Queue names are looked up through the `QueueDirectory` the server is built with, which knows no Queue until Queue resources exist.
