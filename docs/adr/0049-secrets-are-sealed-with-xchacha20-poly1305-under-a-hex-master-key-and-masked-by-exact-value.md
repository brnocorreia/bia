# Secrets are sealed with XChaCha20-Poly1305 under a hex master key and masked by exact value

The internal Secret Provider (ADR-0017) stores each value in the `secrets` table sealed with XChaCha20-Poly1305 (RustCrypto `chacha20poly1305`), under a fresh 24-byte random nonce stored beside the ciphertext, with the Secret's name as associated data so a ciphertext cannot be moved to another name; a database dump without the key reveals nothing. The key is `BIA_MASTER_KEY` (`master_key` in the config file): exactly 64 hex digits, 32 bytes, as `openssl rand -hex 32` prints, the same shape as other bia credentials. A malformed key stops startup without echoing it, and so does a database that holds Secrets when no key is set; with no key and no Secrets the server starts, the write route answers `master_key_missing` (503), and a Step that reads a Secret fails `fatal`. Rotating the key is not supported yet: it means re-setting every Secret; envelope encryption with a key id column is the intended way and the table can take it later. Names are `[A-Za-z_][A-Za-z0-9_]*` up to 128 characters, so every name is readable as `secrets.NAME`. The trait the interpreter resolves through stays `SecretResolver` in `bia-engine` (its implementations reach Postgres or the network, so it cannot live in `bia-core`), and the internal provider is `InternalSecrets` there, over the repository and cipher in `bia-store`. Resolved values are kept out of the Timeline by construction (Timeline `input` records Templates as written, and Dry Run uses placeholders), and the interpreter additionally replaces every resolved value with `***` in the Output and in the error (message and details) of the Attempt before they are stored. Masking is exact-value on JSON strings and object keys, so an Action that transforms the value (encodes, splits, re-cases) before echoing it is not caught; this is the contract Actions are written to, and it is why Secrets belong in Params and nowhere else (ADR-0011). Routes are `PUT /v1/secrets/{name}` and `DELETE /v1/secrets/{name}` for `admin`, and `GET /v1/secrets` for `admin` and `agent`: an agent authoring a Definition needs the names to reference, they are not sensitive, and ADR-0008 gives `agent` read access, so `list_secrets` is the one Secret MCP tool and no tool or route returns, sets or deletes a value for an agent. No response carries a value; replacing is the only way to change one, and the CLI reads the value from standard input or `--file`, never an argument.
