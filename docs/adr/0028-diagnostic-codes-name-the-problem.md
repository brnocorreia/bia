# Diagnostic codes are snake_case phrases that name the problem

Diagnostic codes are a public contract that agents match on, so their shape is fixed once the first ones ship. A code is a lower `snake_case` English phrase that names the problem rather than the fix, such as `unknown_queue`, `duplicate_step_id` or `step_may_not_have_run`. It has no layer prefix, number or severity, because severity can depend on the target (an `unknown_queue` is a warning on a Draft and an error at publish) and a problem may move between layers without its meaning changing. One code covers one problem an agent would fix in one way, so a single code carries what varies in its message and `path`, and a new code is added only for a problem that needs a different fix. The catalogue is the `bia_core::validation::Code` enum, listed in `docs/dsl.md` and snapshot-tested, so a code cannot disappear unnoticed. Names read well in prose and logs, and numbered codes (`E0042`) would need a lookup table to mean anything to an author or an agent.
