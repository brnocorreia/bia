# The CEL dialect: JSON mapping, Template syntax and bounded cost

Expressions run on cel-rust (the `cel` crate), the maintained Rust CEL implementation, parsed with its Pratt parser, because its default ANTLR parser overflows a 2 MiB thread at a dozen nested parentheses in a debug build. The dialect is the CEL standard library (with `timestamp`, `duration` and `matches`) plus the `strings`, `math` and `base64` extensions. `lists` is left out because `lists.range(n)` allocates without bound, and `math.greatest`/`math.least` are unavailable because they are macros the Pratt parser does not expand. JSON numbers with no fractional part become `int` (or `uint` beyond `int64`), so `steps.a.output.count + 1` works, and every other number becomes a `double`. Results go back to JSON with `bytes` as base64, `timestamp` as RFC 3339 and `duration` as a seconds string such as `"1.5s"`. A Template is one-expression, and keeps its type, only when the whole string is a single `{{ … }}`. Otherwise strings are inserted as they are and every other value as compact JSON. `{{` has no escape (a literal is `{{ '{{' }}`), and the closing `}}` is found outside CEL string literals and braces the Expression opened. Evaluation is bounded by source length (8 KiB), syntax-tree depth (32 levels, so the evaluator's recursion stays within a small stack) and a cost budget (100,000 units). cel-rust has no cost tracking, so after parsing, each comprehension is rewritten to call an internal function, named with an `@` that CEL source cannot write, once per iteration. Each call costs 1 plus the size of the value the iteration produces. Comprehensions are the only construct whose work can grow beyond the Expression's own size.

## Consequences

- These choices fix what Expressions mean to users. Changing the number mapping, the Template rules or the extension set is a DSL change that goes through `schema_version`.
- Exceeding the budget fails the evaluation even when an outer `||` or `&&` would have absorbed the error, so a runaway Expression never succeeds by accident.
- The Pratt parser is `#[doc(hidden)]` in cel-rust 0.15, so upgrading `cel` must recheck it, along with the shape of the macro expansions the cost rewrite relies on.
- Evaluation errors carry types rather than values, and anything left is redacted against the scope's Secrets, so Secrets stay out of errors.
