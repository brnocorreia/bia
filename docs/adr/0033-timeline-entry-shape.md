# Timeline entries: one per Attempt, Run-level entries without a Step, and coded errors

The Timeline is what operators and agents read to explain a Run, and it becomes an API contract (BIA-22), so its entry shape is fixed here. An entry records one Attempt: Step id, iteration path, Attempt number, Action, status (`succeeded`, `failed`, `skipped`), input, Output or error, and start and finish times, from which its duration follows. An entry that concerns the Run as a whole, such as input rejected before any Step ran, has no Step, Attempt or Action; it records the Run input as its input. An error is the Action's `ActionError` as it serialises (`class`, `message`, optional `details`); an error the interpreter raises itself also carries a stable `code` agents can match on (`invalid_input`, `timeout`, `unknown_action`, `disabled_action`, `invalid_template`, `invalid_params`, `unknown_secret`, `unsupported_step`), and like Diagnostic codes these are added freely and renamed only with an ADR (ADR-0028). The input is the Params with their Templates resolved, except that every Template reading `secrets` is recorded as written: substituting a marker for the Secret alone would still store anything computed from it (its length, an encoding, a substring), so the whole Template stays unevaluated in the record while the Action receives the resolved value. Outputs are recorded as the Action returned them, so an Action must never return a Secret.

## Amendments

- Status `cancelled` joins `succeeded`, `failed` and `skipped` (ADR-0036). A cancelled Run has exactly one such entry: the Attempt its cancellation cut short, with its input and no error, or, when no Attempt was in flight, a Run-level entry with no input. The status says what happened, so no error code is added for it.
