# Tokens are random and stored as SHA-256, the first admin Token is bootstrapped through the API with a server-side key, and handlers declare their Scope

Token format, storage and the bootstrap path are hard to change once installs hold Tokens, and the bootstrap path is the one place ADR-0007 could give way, so they are fixed here. A Token value is `bia_` followed by 64 hex digits of OS randomness, a prefix secret scanners can match; it is returned once, by the request that creates it, and the `tokens` table keeps only its unkeyed SHA-256 with its Scope, name, creation, last use (recorded to the minute, so a request does not always write) and revocation. A fast unkeyed hash is enough because a value carries 256 random bits, so a leaked hash cannot be reversed by guessing, and lookups need no server key to keep and rotate; slow password hashes protect low-entropy secrets and would only add latency to every request. The first admin Token comes from `POST /v1/tokens/bootstrap`, authenticated with a bootstrap key the operator gives `bia serve` in `BIA_BOOTSTRAP_KEY` (at least 32 characters, held in memory only as a hash); `bia token create --bootstrap` calls it with the same variable, so `bia token create` stays an API client and only `serve` and `migrate` touch Postgres. The endpoint refuses with `already_bootstrapped` while any unrevoked admin Token exists, under an advisory lock so concurrent calls mint at most one, so the key cannot mint a second admin Token, silently or otherwise; once every admin Token is revoked it works again, which is the deliberate recovery path, and an operator who wants none removes the variable, which turns the endpoint off (`bootstrap_disabled`). We rejected an unauthenticated first-come bootstrap, which hands admin to whoever reaches a freshly exposed server first, and a `token create` that writes to Postgres, which would break ADR-0007 for a problem the API can solve. Each handler declares its requirement by taking an `Admin`, `Agent` or `Webhook` extractor first, so the rule sits on the handler and its OpenAPI `security`; `admin` passes every route, `agent` every route but publishing, activation and administration (Tokens, and later Secrets), and `webhook` only `/hooks/{workflow_id}/{trigger_id}` for the Trigger it is bound to. Public routes are `/health` and `/ready`, which orchestrators call without credentials, `/openapi.json`, which is the same for every install, and bootstrapping; `/v1/schema` needs `admin` or `agent`, since its Action catalogue describes this server's configuration. A test walks the OpenAPI document and fails if any other route answers without a Token. CORS allows only the origins in `BIA_CORS_ORIGINS` (or `*`), and never credentials, since Tokens travel in the `Authorization` header a page must set itself. (Superseded in part by ADR-0062: the Bootstrap Key and `POST /v1/tokens/bootstrap` are gone, and first-run setup through a Setup Link creates a User that owns every Token; the public routes are now the probes, `/openapi.json` and `/v1/setup`. The Token format, its storage and the Scope extractors stand.)
