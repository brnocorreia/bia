# Blocks are typed in the schema and DSL objects are closed

A Step is one flat object discriminated by `action`. The six Blocks (`flow.branch`, `flow.switch`, `flow.parallel`, `flow.foreach`, `flow.loop_until`, `flow.try`) are a closed set whose nested fields sit at the Step level, take no `params`, and are typed per Action in the JSON Schema (a `oneOf` keyed on `action`). Every other Action, `flow.subworkflow` and `human.*` included, is an ordinary Step whose `params` are an open object checked later against the Action's param schema. Every DSL object rejects unknown fields (`additionalProperties: false`), and `null` is treated as an absent field. Typing Blocks in the schema lets agents and the editor author control flow from `GET /schema` alone, and the interpreter can rely on Block shapes without re-checking them. Closed objects turn a typo such as `retires` into an error instead of a silently ignored field. Both are hard to loosen later without breaking stored Definitions, and loosening is the cheap direction. The cost is that adding a Block means a schema change, which is acceptable because new control flow already needs interpreter work and a `schema_version` decision.
