# API commands read `url` and `token` from the config file or `BIA_URL` and `BIA_TOKEN`, and report through exit codes and `--json`

Every `bia` subcommand but `serve` and `migrate` is a client of the API (ADR-0007), so it needs the server's address and a Token, and it must be scriptable. They follow ADR-0037's naming in the file `--config`/`BIA_CONFIG` already names: the top-level keys `url` and `token` are `BIA_URL` and `BIA_TOKEN`, so one file can serve both a server and its operator, and `serve` accepts and ignores them. Precedence, lowest first: the default `http://127.0.0.1:8080`, the file, the variable, then the global `--url` flag; the Token has no flag because argv is readable by other users. Without `--config` no file is read, so there is no implicit location to explain or to leak a Token from. Output is text for people and, with the global `--json`, a single JSON document whose shape is the API's (plus `results` for `validate` and `applied` for `apply`); a failure under `--json` is `{"error": {"code", "message", "diagnostics"}}` on stdout, with the same code the API uses, or `unreachable` and `cli_error` for what the API never saw. Exit status is 0 on success and 1 when a command fails, when validation finds an error Diagnostic, when `apply` saves a Draft with error Diagnostics, or when a Dry Run ends `failed`; usage mistakes exit 2. `workflow apply -f` takes files and directories (recursive, `.json`, `.yaml`, `.yml`), converts YAML client-side with `bia-core`, and for each Definition replaces the Workflow's latest Version when it is a Draft, reports `unchanged` when it is a Published Version holding the same Definition, and otherwise creates a new Draft, so applying twice never piles up Versions; `--publish` and `--activate` only call the publish and activate routes with the caller's Token, so Scopes apply unchanged. Diagnostics point at `file:line` for YAML by walking the file's indentation, since the server only sees JSON; for anything it cannot place it names the nearest ancestor. Files with a top-level `kind` are refused until their resource exists (ADR-0025).

## Amendments

- `bia login` stores a login in the OS keychain or `credentials.json` in `$BIA_CONFIG_DIR`, `$XDG_CONFIG_HOME/bia` or `~/.config/bia`, which breaks "no implicit file" for that one location. `BIA_TOKEN` or the config file's `token` still wins over it, and the Token still has no flag (ADR-0068).
- `serve` also accepts `public_url` and `ui_url` (ADR-0063); `BIA_BOOTSTRAP_KEY` and `--bootstrap` are gone (ADR-0062).
