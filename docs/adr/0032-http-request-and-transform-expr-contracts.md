# The contracts of `http.request` and `transform.expr`

Param schemas are user-facing and may only grow during 0.x (ADR-0016), so the first builtin Actions keep theirs small and closed. `http.request` takes `url`, `method`, `headers`, `query`, a body as either `json` or `text` (never both), `auth` as a union tagged by `type` (`basic` or `bearer`, so new schemes are added as new tags), a `timeout` Duration (default `30s`) and `success_statuses`, the statuses outside 2xx that also succeed. 5xx, 408 and 429 statuses, network errors and timeouts are `retryable`; every other status, invalid Params, a body over 10 MiB and too many redirects are `fatal` (ADR-0012, amended here for 408 and 429), with the response attached as the error's `details` so `flow.try` can read it. The Output is `status`, `headers` (lowercase names, repeats joined with `, `), `body` and `body_encoding`: `json` when the content type is JSON and the body parses, `text` for any other UTF-8 body and `base64` otherwise, so a JSON string body and a text body stay distinguishable. TLS is always verified against the system trust store and up to ten redirects are followed; neither is configurable yet, because adding an opt-out later is additive and removing one is not. `transform.expr` takes an `expression` and an object of `values`, which the Expression reads as `values`, a variable only this Action's scope has, so its Expressions cannot be confused with the Run's own scope. The HTTP client is `reqwest` with rustls, the mainstream async client already built on the tokio stack bia uses.
