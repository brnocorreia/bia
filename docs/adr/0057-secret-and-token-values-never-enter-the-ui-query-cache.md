# Secret and Token values never enter the UI's query cache

The Secrets and Tokens screens handle the two values the UI must not keep: a Secret's value (ADR-0017, write-only) and a new Token's value (shown once). TanStack Query retains a mutation's variables and result in its cache, so `useMutation` would hold both for the cache lifetime. We send them through plain functions (`putSecret`, `createToken`) instead: the Secret value is read from an uncontrolled password input (`autocomplete="new-password"`) and cleared as soon as it is sent, and a created Token lives only in the form's component state until the user dismisses it, so a reload or navigation drops it. Both screens are wrapped in `RequireAdmin` (ADR-0053); the server still enforces the Scope. The e2e suite asserts that no response body, page content or browser storage contains either value.
