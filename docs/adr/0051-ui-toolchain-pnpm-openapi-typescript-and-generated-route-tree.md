# The UI uses pnpm, `openapi-typescript` with `openapi-fetch`, and a route tree that is generated and not committed

Several UI issues are built in parallel and the choices outlive them, so they are fixed here. pnpm is the package manager (CONTRIBUTING already names it), with a committed lockfile. API types come from `openapi-typescript` run on the committed `crates/bia-server/openapi.json`, and requests go through `openapi-fetch`, whose client is typed by those paths; we chose them over `orval` or a hand-rolled client because they emit types only, with no runtime code to review, and over a hook generator because screens already use TanStack Query directly. The generated `src/api/schema.gen.ts` is committed and CI fails when regenerating it changes the file, so a handler change cannot land without its UI types. TanStack Router's file-based route tree (`routeTree.gen.ts`) is git-ignored and generated by `tsr generate` before typecheck, lint, test and build: committed, it would conflict in every PR that adds a screen, and a route file is already the source of truth. A screen is one `src/routes/_app.<name>.tsx` file and appears in the navigation by setting `staticData.nav`, so adding one edits no shared file. The runtime `config.json` is fetched from the site root (`/config.json`) and must be served from there; the bundle uses absolute asset paths, so hosting under a sub-path is not supported yet. TypeScript is held at 6.x because `openapi-typescript` needs the compiler's JavaScript API, which 7.x does not offer.
