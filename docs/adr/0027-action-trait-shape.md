# The `Action` trait returns boxed futures and describes itself with raw JSON Schema

Every Action implements one contract, which validation, `GET /schema`, Dry Run and the interpreter all read, so its shape is hard to change. `bia_core::action::Action` has two methods: `descriptor()` and `execute(call, cancel)`, which returns a `Pin<Box<dyn Future + Send>>`. Native `async fn` in traits is not yet object-safe, the Action Registry hands out `Arc<dyn Action>`, and a hand-written boxed future avoids taking on a proc-macro (`async-trait`) for one method. The call (`ActionCall`: resolved Params, Idempotency Key, Run context), the Output (`serde_json::Value`), the error (`ActionError`, classified `retryable` or `fatal`) and the descriptor all serialise, so an Action Server or a WASM guest can carry them unchanged (ADR-0006). The cancellation token is `tokio_util`'s `CancellationToken`, which pulls in only tokio's `sync` feature. Param and output schemas are `schemars::Schema` values, raw JSON Schema rather than Rust types, because Actions served over HTTP have no Rust types to derive from; builtin Actions may still derive theirs with `schemars`. Whether an Action can change the world is an `effect` of `pure` or `side_effecting`, declared per Action, and Dry Run gives side-effecting Actions a Mock. `ActionRegistry` is a trait, so builtin Actions and Action Servers can sit behind one interface; `InMemoryRegistry` covers the builtin case and keeps dangerous Actions disabled until enabled by name (ADR-0014).
