# The editor Dry Runs its current text, with Mocks written as the API's own JSON

The Dry Run panel sends the editor's parsed content to `POST /v1/dry-run` (ADR-0046), so an unsaved Definition can be tested, and a Definition that does not validate comes back as `invalid_definition` whose Diagnostics the panel lists in place of a Timeline. Mocks are edited as JSON text per Step id in exactly the API's format (`{ "output" }`, `{ "error" }`, `{ "attempts" }`), with buttons that start one from the Action's first example, a failure, or fail-once-then-succeed, rather than a form that would hide the format and could not be copied to a CLI file. The Step ids offered are the Steps of the parsed Definition that call a non-`flow.*` Action (nested Blocks and `on_error` included), matching what the API accepts. The last input and Mocks are kept per Workflow in `localStorage` (`bia.dryRun.<id>`, `(new)` before a Workflow exists) as a convenience only: any storage failure means an empty panel, and nothing is stored server-side.
