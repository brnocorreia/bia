# MCP tools call the API router with the caller's Token, and send_event and list_queues wait for their endpoints

`/mcp` is the `rmcp` streamable HTTP service (v3, stateless: no session mode, JSON responses, no `Host` allow-list, since the Token and not the network location authenticates). Each request must carry `Authorization: Bearer <Token>` with an `admin` or `agent` Token, checked before MCP sees it (401 or 403 with the API's error body otherwise), and a `webhook` Token is refused. A tool builds exactly one API request from its arguments and sends it, with the caller's own `Authorization` header, to the in-process API router (the same `Router` that serves `/v1`, without CORS), then returns the response body as `structuredContent` (and as text), with `isError` set when the status is not 2xx and the body being the API's error body (`code`, `message`, `diagnostics`). Scopes, validation, Diagnostics and error codes are thereby the API's by construction: a tool cannot do what its endpoint refuses, a revoked Token stops working on the next call, and there are no tools for publishing, activating or administering Tokens, so an `agent` Token has nothing to attempt (the descriptions tell the agent to ask a human). The tools are `get_schema`, `list_actions` (the `actions` of `GET /v1/schema`, the only projection), `list_workflows`, `get_workflow`, `list_versions`, `get_version`, `validate_workflow` (`definition`, or `workflow_id` + `number`; optional `target`), `create_draft` (`workflow_id`, `definition`), `replace_draft`, `dry_run` (`definition`, or `workflow_id` + `number`; optional `input`, `mocks`), `diff_versions` (`workflow_id`, `from`, `to`), `trigger_run` (`workflow_id`, optional `input`, `trigger_id`), `get_run`, `list_runs`, `list_failures` (filters as the query parameters), `retry_run`, `resume_run` and `cancel_run` (`run_id`); arguments are the endpoint's path, query and body names, bad arguments are tool errors with `code: malformed_request`, and path segments are percent-encoded so an argument cannot address another route. Tool names, descriptions and argument names are an agent-facing contract like Diagnostic codes: a snapshot test shows every change, and renaming or removing a tool needs an ADR. `send_event` (BIA-41) and `list_queues` (BIA-35) have no endpoints yet, so they are not registered; the issues that add the endpoints add the tools, and a tool that answered "not available yet" would only make agents plan around something that does not exist. `bia mcp` forwards each JSON-RPC line from stdin to `{url}/mcp` with the Token from `BIA_TOKEN` or the config file (ADR-0047) and writes every reply to stdout, answering a failed request with a JSON-RPC error that quotes the API's code and message.
