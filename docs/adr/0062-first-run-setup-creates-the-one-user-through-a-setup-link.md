# First-run setup creates the one User through a Setup Link logged by `bia serve`, replacing the Bootstrap Key

How a fresh install gets its first credential, and how a locked-out operator gets back in, is fixed before sign-in and Sessions build on it; this supersedes the bootstrap path of ADR-0043, whose Token format, hashing and Scope-extractor rule stand. Credentials now belong to a User: a `users` table holds the admin with an argon2id password hash (the `argon2` crate's defaults, OWASP's recommendation), every Token carries `user_id`, and the migration deletes the Token rows minted under the Bootstrap Key, which nothing depended on yet. While no User has a password, the `api` Role logs a Setup Link, `{ui_url}/setup?code=<code>` (ADR-0063), and `POST /v1/setup` takes `{code, password}` without a Token, so only someone who can read the server's logs can set up, rather than whoever reaches a freshly exposed port first. The code is `<start>-<secret>`: `secret` is 128 random bits, and `start` is random per server start, so a code from before a restart is refused as `setup_code_expired`, distinct from a wrong one (`invalid_setup_code`), both 403; the server keeps only the code's SHA-256, in memory, compares it in constant time, and makes a new one on every start, so a leaked link stops working at the next restart and nothing secret is stored. With several API processes each logs its own link, valid only on that process. The endpoint refuses with `already_set_up` (409) once a User has a password, deciding under an advisory lock so concurrent calls create at most one User, and refuses a password under 12 characters, counted as characters, with `password_too_short` (422), the only rule, since length is what resists guessing. The Setup Link is the one place a credential is logged on purpose; the password and the code are never echoed in an error body, so the endpoint replaces axum's JSON rejection text, which can quote the body, with a fixed message. Recovery is `bia serve --reset-admin`, which clears the password and revokes all the User's Tokens before serving and then logs a new link; `serve` doing it itself keeps ADR-0007 intact, and `bia setup` is an API client like any other command. The Bootstrap Key, `POST /v1/tokens/bootstrap`, `bia token create --bootstrap` and the error codes `bootstrap_disabled` and `already_bootstrapped` are removed, which is why this ADR exists for codes agents may have matched (ADR-0042). We rejected keeping the Bootstrap Key, an extra operator-managed secret whose only use is a copy-paste ritual, and persisting the code in Postgres, which would outlive restarts and need cleanup for no gain. Until sign-in exists, setup also returns one `admin` Token, shown once, so the API stays usable; sign-in removes that.
